# PocketPal 香港市場研究及產品 Brief

研究日期：2026-09-09。範圍：公開資料研究、政府文件需求、競品官方功能、目前 checkout 靜態閱讀。未訪問客戶、未測試競品、未驗證付費意願；以下功能排序屬產品假設，並非市場調查排名。

## 定位建議

讓香港自僱人士及沒有專職簿記員的小型服務公司，將日常收入、支出和證明文件整理成可交付的紀錄包。

建議首輪聚焦自僱及 1–5 人服務團隊（此人數為產品切入假設）。一般家庭保持簡單記帳；公司沿用同一套資料收集及核對能力，逐步增加收款管理。個人資助和企業資助各有不同文件要求，不可共用一個「符合政府要求」標記。

## 競爭及差異

- Money Lover 已提供 CSV 匯出。[7] 匯出本身不足以構成差異。
- Xero 香港版已有發票、費用及銀行對帳等功能。[8]
- Zoho Books 官方展示由圖片／文件辨識並建立相關交易。[9]
- 香港定位的 BizBooks 亦宣傳 AI 單據記帳及報表。[10] 此為廠商自述，未驗證其準確率或合規宣稱。

可驗證的差異假設：不懂會計的人也能快速整理指定期間的完整紀錄，交給會計師或用於準備申請，且清楚知道缺甚麼。衡量整理時間及補件次數，不以 AI 功能數量為成功指標。

## 現有程式觀察

- Receipt 已有 income／expense；Dashboard 有收入、支出及淨額統計。
- SettingsView 有 CSV、JSON 及 CSV 加圖片資料夾匯出。`makeExportFolderWrapper` 只接受 `.image`，會略過 PDF；不存在的原檔也直接略過。不能稱為完整原檔匯出。
- Settings CSV 有 Type 欄位；TaxExportService 的另一份 CSV 缺少 transaction kind 欄位，交付時需要明確区分收支。
- 正式稅務匯出已以已核對狀態篩選。完整帳簿和已核對紀錄需分開說明，避免用戶誤以為所有資料均已匯出。
- AccountingView 已有 banking、sales、bills、projects 等模組及發票狀態程式；有模組不代表銀行串接、完整對帳或真機流程已通過驗收。
- 此 checkout 有既有未提交修改，本輪只新增此文件，未改 app、未 build、未進行真機 QA。

## 首輪 PRD：指定期間完整紀錄包

使用情境：自僱用戶月底把某段期間的收支及原始文件交給第三方。

流程：選工作區 → 選期間 → 預覽收入／支出、筆數和缺件 → 選完整紀錄或已核對紀錄 → 匯出資料包。

驗收條件：

1. 以交易日期篩選，香港日期邊界一致；無日期紀錄另外列出並讓用戶決定是否包含，不能默默排除。
2. CSV 清楚分開收入與支出；摘要稱淨收支，不稱應課稅利潤；缺金額不可當成零。
3. 圖片與 PDF 原檔均保留；每筆交易以穩定 ID 對應索引及附件。
4. 找不到原檔時，預覽及缺件清單均列出；若仍匯出，標記資料不完整。
5. 全部／已核對匯出各顯示筆數、排除筆數、期間及工作區。
6. 匯出不能改動原始紀錄；用混合收支、圖片、PDF、缺檔及跨月資料驗證合計與索引。

首輪不新增自動判斷資助資格、官方表格自動提交、銀行登入串接或全面薪酬／存貨系統。個別資助模板在確認首個計劃和用戶之後再做。

## 需求驗證方案

訪問建議：5 名自僱人士、5 名微企負責人、2 名簿記／會計從業員；若主攻個人資助，另找 3 名近期申請者。這是待執行計劃，並非已完成訪談。

請對方展示最近一次整理紀錄的實際過程：資料從哪裡來、花多久、誰要求補件、現有工具及費用、哪一步最常放棄。用同一批去識別化紀錄試做新流程。

建議初步成功門檻（產品目標，非市場基準）：整理時間中位數下降至少 50%；測試資料的金額及附件索引正確率 100%；用戶可在無指導下完成匯出；會計師能追溯指定交易；記錄真實付費承諾及四週持續使用。先不下定價結論。
